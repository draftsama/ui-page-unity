<objective>
Close the two remaining Phase 1 reliability bugs, both of which are about state that outlives the
thing it describes.

BUG-03: `SetShow` caches a `CanvasGroup` and dereferences it on the next line
(`Runtime/UIPage.cs:104-109`). The re-fetch on line 104 handles a stale reference but not an absent
component, so if the CanvasGroup was destroyed and not replaced, `GetComponent` returns null and line
107 throws an unhandled `NullReferenceException`. The same raw dereference happens in `ShowPageAsync`
(line 142) and five more times inside the transition (lines 293-294, 330-331, 343-345).

BUG-02: the static `s_PageRegistry` survives a play-mode boundary whenever Unity 6's Enter Play Mode
Options disable domain reload. `Awake` then scans that stale list and reads `m_IsOpened` off pages
destroyed in the previous session - a destroyed MonoBehaviour's managed fields are still readable, so
`hasOpened` comes back true and the default page never shows. The editor cleanup that should catch
this hangs off a lazy `static UIPage()` constructor (`Runtime/UIPage.cs:27-41`) that only runs once the
type happens to be touched, and it resets `m_IsTransitionPage` only - never the `m_IsOpened` and
CanvasGroup state a mid-transition stop left behind.

**Phase goal (verbatim from ROADMAP.md Phase 1):** Users of the package no longer hit the three known
reliability failures - transitions don't desync, stale editor state doesn't leak across play
sessions, and destroyed components don't crash the page.

Purpose: ROADMAP success criteria 2 and 3.
Output: A `Runtime/UIPage.cs` where every CanvasGroup access either recovers or fails loudly, and where
static page state cannot cross a play-mode boundary.
</objective>

    Edit A - a runtime reset that does not depend on the editor. Add a private static method

    `s_PageRegistry` and `s_TransitioningGroups`. `SubsystemRegistration` runs before the first scene

    Edit B - make `Awake` immune to carry-over entries. After the group list is obtained or created and
    before the `hasOpened` scan, prune destroyed entries with `list.RemoveAll(_ => _ == null);` - the
    `UnityEngine.Object` equality overload makes this catch destroyed pages, not just null references.
    Then harden the scan itself to `list.Any(_ => _ != null && _ != this && _.m_IsOpened)`. Without
    both, a destroyed page from the previous session still reports `m_IsOpened == true` from its
    surviving managed object, `hasOpened` comes back true, and the default page never shows.

    Edit C - replace the lazy editor hook. Inside the existing `#if UNITY_EDITOR` region of the `UIPage`
    class, delete the parameterless static constructor and its inline lambda, and put in their place:
      - `private static void InitializeEditorHooks()` decorated with `[UnityEditor.InitializeOnLoadMethod]`.
        Unlike a static constructor - which C# runs lazily on first use of the type, so the subscription
        may not exist at all when play mode ends - this runs on every editor domain load and every
        script recompile. Its body unsubscribes then subscribes
        (`EditorApplication.playModeStateChanged -= OnPlayModeStateChanged;` then `+=`) so a persisted
        domain cannot end up double-subscribed.
      - `private static void OnPlayModeStateChanged(PlayModeStateChange _state)` handling
        `PlayModeStateChange.EnteredEditMode` only. This fires after Unity has restored the serialized
        scene, which is the right moment to repair what play mode left behind. Its body:
        clear `s_PageRegistry` and `s_TransitioningGroups`; then for each page from
        `Object.FindObjectsByType<UIPage>(FindObjectsInactive.Include, FindObjectsSortMode.None)`,
        capture `var wasTransitioning = page.m_IsTransitionPage;`, set `page.m_IsTransitionPage = false;`,
        and only `if (wasTransitioning)` call `page.SetShow(page.m_IsDefault);`.

    The `wasTransitioning` condition is the whole point of the repair and must not be widened. A page
    caught mid-transition has inconsistent alpha, interactable, blocksRaycasts and `m_IsOpened`, so
    resetting it to its default baseline is a genuine repair. A page that was NOT mid-transition holds
    the state the developer authored at edit time - including a deliberately previewed non-default page -
    and rewriting that is data loss, not a fix.

    For the same reason the repair stays in memory: it must not mark the scene, its objects, or any
    prefab dirty, and must not record an undo entry. Persisting it would silently rewrite the
    developer's authored scene asset every time they stop play mode.

    Finally, in `OnDestroy`, replace `defaultPage?.SetShow(true);` with an `if (defaultPage)` guard. The
    C# null-conditional operator bypasses `UnityEngine.Object`'s equality overload, so `?.` happily
    invokes a method on an already-destroyed page; the implicit bool conversion does not.

## Naming Conventions

**Files:**
- Pattern: `PascalCase.cs` - All files follow Unity C# naming
- Examples: `UIPage.cs`, `UITransitionFade.cs`, `TransitionInfo.cs`

**Classes:**
- Pattern: `PascalCase` - Public classes, components
- Examples: `UIPage`, `UITransitionFade`, `TransitionInfo`, `UIPageEditor`

**Interfaces:**
- Pattern: `IPascalCase` - Lifecycle callback interfaces
- Examples: `IPageShowBegin`, `IPageShowEnd`, `IPageHideBegin`, `IPageHideEnd`

**Private Fields:**
- Pattern: `m_PrivateName` - Serialized or internal state
- Examples: `m_GroupName`, `m_IsOpened`, `m_CanvasGroup`, `m_RectTransform`
- Rule: Prefix with `m_` to distinguish from parameters and local variables

**Public Properties:**
- Pattern: `PascalCase` - Read-only properties over private fields
- Examples: `GroupName`, `IsOpened`, `IsDefault`, `IsTransitionPage`

**Static Fields:**
- Pattern: `s_StaticName` - Class-level (registry, singletons, caches)
- Examples: `s_PageRegistry`, `s_CircleTexture`, `_instance`
- Note: Some inconsistency in singleton naming (`_instance` vs `s_` prefix)

**Methods:**
- Pattern: `PascalCase` - Public methods, `camelCase` or `PascalCase` for helpers
- Examples: `OpenPage()`, `GetCurrentPage()`, `TransitionPageAsync()`
- Async Pattern: Async methods suffixed with `Async` (e.g., `OpenPageAsync()`, `ShowPageAsync()`)

**Enums:**
- Pattern: Nested public enums in data classes
- Example: `TransitionInfo.TransitionType` with values `Fade`, `CrossFade`, `Slide`

**Local Variables:**
- Pattern: camelCase for local vars, UPPER_SNAKE_CASE for constants
- Examples: `lineHeight`, `currentY` (local UI layout vars)
- Note: Some prefixes used for clarity: `_overrideTransitionInfo` (parameter), `hasOpened` (bool result)

## Where to Add New Code

**New Transition Type:**
1. Add enum value to `TransitionInfo.TransitionType` (`Runtime/TransitionInfo.cs`, line ~12)
2. Add serialized fields to `TransitionInfo` class for new parameters (`Runtime/TransitionInfo.cs`, line ~22-29)
3. Add property drawer condition in `TransitionInfoEditor.OnGUI()` (`Runtime/TransitionInfo.cs`, line ~464-477)
4. Add implementation branch in `UIPage.TransitionPageAsync()` (`Runtime/UIPage.cs`, line ~308-350)

**New Lifecycle Callback:**
1. Create interface following pattern `IPageXxxBegin` / `IPageXxxEnd` (`Runtime/UIPage.cs`, near line ~650)
2. Add `GetComponents<>()` invoke in `UIPage` at desired point (e.g., line ~301-358 during transition)
3. Document when callback fires in code comment

**Derived UIPage Component:**
1. Create new `.cs` file in `Runtime/`
2. Inherit from `UIPage` (e.g., `public class MyCustomPage : UIPage`)
3. Override `Awake()` / lifecycle methods, call `base.Awake()` first
4. Implement lifecycle interfaces if custom logic needed
5. Attach to GameObject alongside CanvasGroup

**New Transition Effect:**
1. Create new `.cs` file in `Runtime/` (e.g., `UITransitionZoom.cs`)
2. Follow `UITransitionFade` singleton pattern for full-screen overlays
3. Or implement transition logic directly in `UIPage.TransitionPageAsync()` branch
4. Reference via `TransitionInfo.m_Type` enum

**Test Script (Not Implemented):**
- Would go in separate `Tests/` folder following Unity best practices
- Use `[Test]` attributes with NUnit3
- Reference `Modules.Utilities` namespace
- Test registry queries, transition state, lifecycle callbacks

## Code Organization Principles

**Namespace:** All code in `Modules.Utilities` — no deep nesting

**Single Responsibility:**
- `UIPage` - Page state and transitions only
- `UITransitionFade` - Fade overlay rendering only
- `TransitionInfo` - Configuration container only

**Stateless vs Stateful:**
- `UIPage` - Highly stateful (open/close state, group membership)
- `UITransitionFade` - Stateful (current fade alpha)
- `TransitionInfo` - Stateless (data container)

**Dependency Injection:** None used; dependencies are:
- Inspector assignments (TransitionInfo on UIPage)
- Component lookups (CanvasGroup, RectTransform via GetComponent)
- Singleton access (UITransitionFade.Instance)
